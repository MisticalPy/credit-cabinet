# Умный кредитный кабинет

Веб-сервис для малого бизнеса (ИП и ООО), разработанный на хакатоне Альфа-Банка. Клиент подбирает кредитный продукт под профиль своей компании, считает платёж, подаёт заявку и следит за её статусом. Система автоматически оценивает заявку (скоринг по мокам ЕГРЮЛ и БКИ) и даёт менеджеру рекомендацию. Окончательное решение принимает менеджер в админке. Клиент видит результат и может принять встречное предложение банка. В интерфейсе также есть чат-ассистент на базе LLM.

Стек: Django 6 и Django Ninja (бэкенд), django-unfold (админка), PostgreSQL 18, React 19 + Vite + TypeScript (фронтенд), nginx, Docker Compose.

## Запуск

Требования: Docker и Docker Compose v2.

```bash
cp .env.example .env
docker compose up --build
```

После запуска доступны:

| Что | Адрес |
|-----|-------|
| Веб-приложение (фронтенд) | <http://localhost:8080> |
| Swagger (документация API) | <http://localhost:8080/api/docs> |
| Админка менеджера | <http://localhost:8080/admin/> |
| Бэкенд напрямую | <http://127.0.0.1:8000> |

Что происходит при старте:

- Сервис `migrate` применяет миграции и сразу запускает `seed`: создаёт менеджера, суперпользователя, 5 кредитных продуктов и 3 демо-клиентов с заявками. Повторный запуск ничего не дублирует.
- Сервис `web` стартует после успешного завершения `migrate`, nginx проксирует в него `/api`, `/admin` и `/static`.

Примечания:

- `compose.override.yaml` подхватывается автоматически. Это dev-режим: код монтируется в контейнер, бэкенд работает на `runserver`, PostgreSQL публикуется на `127.0.0.1:5432`.
- Если порт 5432 занят, запустите без override: `docker compose -f compose.yaml up --build` (Postgres тогда наружу не публикуется, бэкенд работает на gunicorn). Порт 8000 для бэкенда задан в `compose.yaml`: при конфликте измените его в разделе `ports` сервиса `web`.
- Чат-ассистенту нужен `LLM_API_KEY` в `.env` (также `LLM_BASE_URL` и `LLM_MODEL`). Без ключа чат отвечает 503, остальные функции работают.
- Сброс данных: `docker compose down -v` удаляет том с базой, при следующем запуске seed создаст демо-данные заново.

## Тестовые аккаунты

Пароль у всех: `AlfaDemo2026`.

| Логин | Пароль | Роль | Ожидаемый исход |
|-------|--------|------|-----------------|
| `manager` | `AlfaDemo2026` | Менеджер | Вход в админку, принятие решений по заявкам |
| `admin` | `AlfaDemo2026` | Суперпользователь | Полный доступ в админке |
| `client_approve` | `AlfaDemo2026` | Клиент | Рекомендация «Одобрить», 100 баллов |
| `client_counter` | `AlfaDemo2026` | Клиент | Рекомендация «Встречное предложение», 65 баллов |
| `client_reject` | `AlfaDemo2026` | Клиент | Рекомендация «Отказать», 35 баллов (просрочки в БКИ) |

У каждого демо-клиента уже заполнен профиль компании и отправлена заявка, которая ждёт решения менеджера (статус «На рассмотрении»).

## Сценарий проверки для жюри

Веб-интерфейс на данный момент покрывает вход и регистрацию, каталог продуктов, ИИ-ассистента и калькулятор-симулятор. Форма заявки в интерфейсе заполняется, но пока не отправляет данные в API. Профиль компании, создание и отправку заявки, статус и принятие встречного предложения проверяйте через Swagger или готовую коллекцию [docs/requests.http](docs/requests.http).

**Клиент**

1. Откройте <http://localhost:8080>, нажмите «Войти» и войдите как `client_counter`. Либо нажмите «Стать клиентом» и зарегистрируйте нового пользователя. Слабый пароль (например, только цифры) будет отклонён.
2. Блок «Кредиты для бизнеса» на главной показывает продукты с условиями. Раздел «Дашборд» содержит калькулятор-симулятор платежей, раздел «Чат» открывает ассистента.
3. Профиль компании: `PUT /api/profile` в Swagger (тип бизнеса, название, ИНН 12 цифр для ИП или 10 для ООО, отрасль, оборот, дата регистрации). У демо-клиентов профиль уже есть.
4. Подбор продукта: `GET /api/products/match` (цель, сумма, срок). Расчёт платежа: `GET /api/products/{id}/calculate`.
5. Заявка: `POST /api/applications`, затем `POST /api/applications/{id}/submit`. При отправке система запускает скоринг и переводит заявку на рассмотрение менеджеру.
6. Статус и история: `GET /api/applications` и `GET /api/applications/{id}`.

**Менеджер**

1. Откройте <http://localhost:8080/admin/> и войдите как `manager`.
2. В разделе «Заявки» выберите заявку со статусом «На рассмотрении». Видны баллы, рекомендация системы, результаты проверок ЕГРЮЛ и БКИ и расшифровка баллов по правилам.
3. В блоке «Решение менеджера» выберите решение, добавьте комментарий для клиента и сохраните. Доступны четыре решения: «Одобрена», «Отказ», «Встречное предложение» (с суммой и сроком, по умолчанию подставляются рекомендованные), «Запрошены данные».

**Результат у клиента**

1. Войдите клиентом и откройте `GET /api/applications/{id}`: виден новый статус и комментарий менеджера.
2. Если выбрано «Встречное предложение», примите его: `POST /api/applications/{id}/accept-offer`. Заявка станет «Одобрена» с новой суммой и сроком. Если выбрано «Запрошены данные», клиент может отправить заявку повторно через `submit`.

Подробные ручные сценарии с ожидаемыми результатами: [docs/test-scenarios.md](docs/test-scenarios.md).

## Правила моков внешних проверок

ЕГРЮЛ и БКИ реализованы как детерминированные функции ([backend/apps/integrations/checks.py](backend/apps/integrations/checks.py)). Результат зависит от последней цифры ИНН:

| Последняя цифра ИНН | ЕГРЮЛ | БКИ |
|---------------------|-------|-----|
| 0 | Ликвидирована (стоп-фактор) | Без просрочек |
| 1-6 | Действующая | Без просрочек |
| 7 | Действующая | 1 просрочка |
| 8 | Действующая | 2 просрочки |
| 9 | Действующая | 3 просрочки |

## Скоринг

Правила описаны в [backend/apps/applications/scoring.py](backend/apps/applications/scoring.py). Баллы суммируются и ограничиваются снизу нулём, максимум равен 100.

| Критерий | Условие | Баллы |
|----------|---------|-------|
| Возраст бизнеса | больше 24 мес. | +30 |
| | от 6 до 24 мес. | +15 |
| | меньше 6 мес. | 0 |
| Доля платежа в месячном обороте | не больше 30% | +30 |
| | не больше 50% | +10 |
| | больше 50% | 0 |
| БКИ | без просрочек | +25 |
| | есть просрочки | -40 |
| ЕГРЮЛ | действующая компания | +15 |
| | ликвидирована | итог 0 баллов и отказ |

Пороги рекомендации:

| Баллы | Рекомендация |
|-------|--------------|
| 70 и больше | Одобрить |
| 40-69 | Встречное предложение (предлагаемая сумма рассчитана так, чтобы платёж не превышал 30% оборота; округляется вниз до тысяч и не больше запрошенной) |
| меньше 40 | Отказать |

Скоринг только советует: решение всегда принимает менеджер.

## Осознанные упрощения MVP

- Один пользователь соответствует одной компании.
- Отрасль выбирается из короткого списка, без справочника ОКВЭД.
- ИНН проверяется по длине и типу бизнеса, контрольная сумма не проверяется.
- Вместо реальных ЕГРЮЛ и БКИ используются моки.
- Решение менеджера принимается только через админку, отдельного интерфейса менеджера нет.
- Веб-форма заявки не подключена к API (см. «Сценарий проверки»).

## Тесты и линтеры

Нужен PostgreSQL по `DATABASE_URL` из `.env`. Для локального запуска достаточно поднять только базу (в dev-режиме она публикуется на `127.0.0.1:5432`):

```bash
cp .env.example .env              # если ещё не сделано
docker compose up -d db
cd backend
uv sync --all-groups              # группа test (pytest, pytest-django) и dev (ruff)
uv run pytest
uv run ruff check .
```

Перечень автотестов: [docs/test-scenarios.md](docs/test-scenarios.md#2-автотесты-pytest).
