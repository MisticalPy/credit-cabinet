# Тестовые сценарии

Документ состоит из двух частей: ручные сценарии для проверки работающего стенда и перечень автотестов pytest.

Общие условия ручных сценариев:

- Стенд запущен: `docker compose up --build` (см. [README](../README.md)).
- Пароль всех демо-аккаунтов: `AlfaDemo2026`.
- Шаги клиента, которые в веб-интерфейсе пока не подключены к API (профиль, заявка, принятие встречного предложения), выполняются через Swagger (<http://localhost:8080/api/docs>) или коллекцию [requests.http](requests.http). Перед запросами, меняющими данные, нужно войти (`POST /api/auth/login`), а после входа обновить страницу Swagger: токен CSRF меняется при входе.
- Решения менеджера меняют демо-данные. Чтобы вернуть начальное состояние: `docker compose down -v`, затем снова `docker compose up --build`.

## 1. Ручные сценарии

| № | Что проверяем | Шаги | Ожидаемый результат |
|---|---------------|------|---------------------|
| M1 | Демо-клиент с рекомендацией «одобрить» | Войти `client_approve`. Открыть `GET /api/applications` | Одна заявка в статусе «На рассмотрении» (`review`). В админке у неё 100 баллов и рекомендация «Одобрить» |
| M2 | Демо-клиент со встречным предложением | Войти `client_counter`. Открыть `GET /api/applications`. В админке открыть его заявку | Статус `review`, 65 баллов, рекомендация «Встречное предложение», заполнена рекомендуемая сумма |
| M3 | Демо-клиент с отказом | Войти `client_reject`. В админке открыть его заявку | Статус `review`, 35 баллов, рекомендация «Отказать». В расшифровке «БКИ: есть просрочки» со значением -40 |
| M4 | Вход менеджера | Открыть <http://localhost:8080/admin/>, войти `manager` | Доступны разделы «Заявки» и «Кредитные продукты». Раздела пользователей нет (у менеджера нет таких прав) |
| M5 | Расшифровка скоринга в админке | Войти менеджером, открыть любую заявку | Блок «Скоринг» показывает баллы, рекомендацию, «Внешние проверки» (статус ЕГРЮЛ, число просрочек БКИ) и построчную расшифровку баллов. Блок «История статусов» (черновик, отправлена, проверка, на рассмотрении) виден суперпользователю `admin` и менеджеру `manager` (у группы «Менеджеры» есть право только на просмотр истории) |
| M6 | Менеджер одобряет заявку | Заявка `client_approve`: в блоке «Решение менеджера» выбрать «Одобрена», написать комментарий, сохранить | Статус «Одобрена». В истории появилась запись с автором-менеджером. Клиент видит статус `approved` и комментарий в `GET /api/applications/{id}` |
| M7 | Менеджер отказывает | Заявка `client_reject`: решение «Отказ», комментарий, сохранить | Статус «Отказ». Блок решения исчез, виден «Итог» с комментарием |
| M8 | Встречное предложение и его принятие | Заявка `client_counter`: решение «Встречное предложение» (поля суммы и срока заполнены рекомендованными значениями), сохранить. Затем войти `client_counter` и вызвать `POST /api/applications/{id}/accept-offer` | После решения статус `counter_offer`. После принятия статус `approved`, в заявке сумма и срок равны встречным, платёж пересчитан. Повторный `accept-offer` возвращает 400 |
| M9 | Встречное предложение вне лимитов продукта | В решении «Встречное предложение» указать сумму больше максимума продукта, сохранить | Сообщение об ошибке с допустимым диапазоном суммы, статус заявки не изменился |
| M10 | Запрос дополнительных данных | Решение «Запрошены данные», сохранить. Клиент вызывает `POST /api/applications/{id}/submit` | Статус `info_requested`; после повторной отправки заявка снова проходит скоринг и возвращается в `review` |
| M11 | Регистрация нового клиента | В интерфейсе: «Войти», «Регистрация», логин `demo_ip`, пароль `Kofe-2026-xyz` (или `POST /api/auth/register`) | Ответ 201, пользователь сразу вошёл, роль `client`. Логин приводится к нижнему регистру |
| M12 | Слабый пароль | Зарегистрироваться с паролем `12345678` | Ответ 400 с текстом ошибки (слишком распространённый пароль, состоит только из цифр) |
| M13 | Занятый логин | Зарегистрировать `Demo_IP` после `demo_ip` | Ответ 400 «Пользователь с таким логином уже существует» (регистр не важен) |
| M14 | Профиль бизнеса | `PUT /api/profile`: ИП, ИНН `770123456781` (12 цифр), оборот 500000, дата регистрации в прошлом | Ответ 201, в ответе рассчитанный `business_age_months`. Повторный `PUT` возвращает 200 |
| M15 | ИНН не той длины | `PUT /api/profile` с типом `ip` и ИНН из 10 цифр | Ответ 422 «ИНН для ИП должен содержать 12 цифр». Для `ooo` ожидается 10 цифр |
| M16 | ИНН уже занят | `PUT /api/profile` другим пользователем с ИНН, который уже есть в базе (например, тип `ip`, ИНН `770123456783` из демо-данных) | Ответ 400 «Профиль с таким ИНН уже зарегистрирован» |
| M17 | Подбор продукта | После M14 вызвать `GET /api/products/match?purpose=working_capital&amount=500000&term=12` | Список подходящих продуктов с расчётом платежа. Без профиля вызов возвращает 400 «Сначала заполните профиль бизнеса» |
| M18 | Калькулятор | `GET /api/products/1/calculate?amount=500000&term=12` (без входа) | `monthly_payment` 46556.89, `total` 558682.68, `overpayment` 58682.68 (продукт «Оборотный без залога», 21%) |
| M19 | Сумма вне условий продукта | `GET /api/products/1/calculate?amount=50000000&term=12` или `POST /api/applications` с той же суммой | Ответ 400 «Сумма для «Оборотный без залога»: от 100000.00 до 3000000.00 ₽». Заявка не создаётся |
| M20 | Срок вне условий продукта | То же с `term=120` | Ответ 400 с допустимым диапазоном срока |
| M21 | Полный путь нового клиента | После M14: `POST /api/applications` (продукт 1, 500000, 12 мес.), `POST /api/applications/{id}/submit`, `GET /api/applications/{id}` | Создано в `draft` (201), после отправки статус `review`, история из четырёх записей. ИНН оканчивается на 1, поэтому ЕГРЮЛ чистый и просрочек нет, скоринг даёт рекомендацию «Одобрить» |
| M22 | Стоп-фактор ЕГРЮЛ | Профиль с ИНН `770123456780` (оканчивается на 0), подать заявку и отправить | 0 баллов, рекомендация «Отказать», в расшифровке «Стоп-фактор: компания не действует по ЕГРЮЛ» |
| M23 | Просрочки в БКИ | Профиль с ИНН, оканчивающимся на 8, подать заявку и отправить | Просрочек 2, в расшифровке «БКИ: есть просрочки» -40, рекомендация снижается |
| M24 | Повторная отправка | `POST /api/applications/{id}/submit` для заявки в `review` | Ответ 400 «Отправить можно только черновик или заявку, по которой запросили данные» |
| M25 | Отправка без профиля | Новый клиент без профиля: создать заявку и отправить | Ответ 400 «Перед отправкой заполните профиль бизнеса» |
| M26 | Изоляция данных клиентов | Войти `client_approve`, открыть `GET /api/applications/{id}` с номером заявки другого клиента | Ответ 404 «Объект не найден» |
| M27 | Защита CSRF | Выполнить `POST` без заголовка `X-CSRFToken` | Ответ 403 «CSRF check Failed» |
| M28 | Доступ без входа | `GET /api/auth/me` без входа; `GET /api/products` без входа | `me` возвращает 401, список продуктов доступен (200) |
| M29 | Чат-ассистент без ключа | Отправить сообщение в чат при пустом `LLM_API_KEY` | Ответ 503 «Ассистент временно недоступен», остальные разделы работают |
| M30 | Идемпотентность seed | Выполнить `docker compose run --rm migrate` повторно | Дубликатов пользователей, продуктов и заявок нет, команда завершается без ошибок |

## 2. Автотесты pytest

Всего 38 тестов в 9 файлах. Тесты используют БД из `DATABASE_URL` (в проекте PostgreSQL).

| Файл | Тестов | Что покрывает |
|------|--------|---------------|
| `backend/tests/test_smoke.py` | 1 | Подключение к базе данных |
| `backend/apps/users/tests/test_api.py` | 8 | Выдача CSRF-cookie; вход, `me`, выход; вход при включённой проверке CSRF; регистрация (роль всегда клиент, логин в нижнем регистре, дубликат логина без учёта регистра); профиль требует входа; создание и обновление профиля; уникальность ИНН |
| `backend/apps/products/tests/test_calculator.py` | 3 | Аннуитетный платёж по эталонному примеру; согласованность итога и переплаты; нулевая ставка |
| `backend/apps/products/tests/test_api.py` | 4 | Подбор продуктов по запросу и профилю; подбор без профиля; сумма вне условий продукта; неактивный продукт даёт 404 |
| `backend/apps/applications/tests/test_scoring.py` | 4 | Скоринг: сильный клиент (100, одобрить); молодой бизнес с тяжёлым платежом (65, встречное); просрочки (35, отказ); стоп-фактор ЕГРЮЛ (0, отказ) |
| `backend/apps/applications/tests/test_api.py` | 5 | Отправка запускает скоринг и переводит в `review`; повторная отправка отклоняется; чужая заявка даёт 404; принятие встречного предложения клиентом; отправка без профиля даёт 400 |
| `backend/apps/applications/tests/test_admin.py` | 3 | Менеджер одобряет заявку в админке; ошибка сервиса показывается менеджеру; встречное предложение вне лимитов продукта ничего не меняет |
| `backend/apps/assistant/tests/test_api.py` | 3 | Чат возвращает ответ LLM (клиент подменён); чат требует входа; ошибка LLM превращается в 503 |
| `backend/apps/core/tests/test_seed.py` | 7 | Команда `seed`: исходы трёх демо-клиентов (баллы и рекомендации, 3 теста по параметрам); рекомендуемая сумма у встречного предложения; менеджер и суперпользователь; права группы «Менеджеры»; идемпотентность |

Запуск:

```bash
cd backend
uv sync
uv run pytest
```

Для PostgreSQL в `.env` должен быть задан `DATABASE_URL`, например при запущенном `docker compose up -d db`.
