# Журнал решений

Короткие записи об архитектурных решениях: дата, решение, почему, какие были варианты.

## 2026-10-26. Статика админки раздаётся через whitenoise

- **Решение:** `WhiteNoiseMiddleware` в Django, `collectstatic` при сборке образа, `STATIC_ROOT=/static`.
- **Почему:** работает и при `DEBUG=False`, не нужен общий volume между `web` и nginx. Каталог `/static` лежит вне `/app`, поэтому bind-mount из `compose.override.yaml` его не перекрывает.
- **Варианты:** раздача статики через nginx с общим volume (больше настройки и точек отказа); `runserver` с `DEBUG=True` (не подходит для gunicorn).

## 2026-10-26. Seed через сервисы, идемпотентный, с гарантированным исходом скоринга

- **Решение:** команда `manage.py seed` создаёт пользователей, продукты и заявки только через сервисный слой и запускается в сервисе `migrate` после миграций. Повторный запуск ничего не дублирует.
- **Почему:** демо-данные проходят те же проверки и скоринг, что и реальные заявки. ИНН, оборот и размер платежа подобраны так, чтобы исход был предсказуем: 100, 65 и 35 баллов. Даты регистрации считаются от текущего дня, поэтому баллы не меняются со временем.
- **Варианты:** фикстуры JSON (обходят сервисы и быстро устаревают по датам); ручное создание данных после запуска (неудобно для проверки жюри).

## 2026-10-26. Фронтенд: multi-stage сборка node в nginx, проксирование в Django

- **Решение:** образ собирается в два этапа (`node` собирает SPA, `nginx` отдаёт статику). Пути `/api`, `/admin` и `/static` проксируются в `web:8000`, заголовок `Host` передаётся как `$http_host`.
- **Почему:** одна точка входа и один origin для браузера, поэтому cookie сессии и CSRF работают без CORS. Host с портом нужен, иначе Django отвечает 403 «Origin checking failed».
- **Варианты:** отдельный домен для API с настройкой CORS (сложнее и хуже для CSRF); dev-сервер Vite в контейнере (не подходит для демонстрации).

## 2026-10-26. Старые README перенесены в docs, новый README написан для жюри

- **Решение:** прежние описания проекта лежат в `docs/overview.ru.md` и `docs/overview.en.md`. Корневой `README.md` содержит запуск, тестовые аккаунты, сценарий проверки и правила скоринга.
- **Почему:** жюри нужна короткая инструкция «запустить и проверить за несколько минут». Подробное описание проекта и roadmap остаются доступными по ссылке.
- **Варианты:** дописать старый README (слишком длинный для быстрой проверки); удалить старые описания (потеряется информация).
